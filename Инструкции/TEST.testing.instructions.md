# TEST — Behavioral evidence

Read Documents 04, 06, 08 and 09 for the affected claim. Write one failing behavior
test first, observe its failure, implement the minimal real path, then rerun it.
The oracle comes from the product contract, not the current implementation.

Use node:test and strict assertions against compiled production code. Temporary
files, controlled clocks/promises and scripted provider I/O are appropriate real
boundaries. No fake replacement engine, fake AgentSession, production test flag,
fixture-name detection or canned success from a missing capability.

Run the smallest affected tests during development, then the relevant static,
build and regression checks before commit. No coverage target or repeated unchanged
checks for their own sake. Include a meaningful negative control for absence/safety
claims: inject a harmless sentinel for privacy and actionable work for Stop.
For zero-provider/feedback claims, observe dispatch/effect boundary counters;
a normal scripted primary turn is the positive control. Scan serialized diagnostic
surfaces through retirement/final flush, not only active in-memory objects.

Keep claims separate:
- Source inspection proves what the pinned source declares.
- Actual Pi loading/tools/lifecycle prove host integration.
- Packed installation proves packaging outside the source tree.
- Synthetic history plus a live assessor proves bounded semantic judgment.
- Bounded live closed-loop work is needed to claim practical improvement.

After actual independent acceptance, qualify the exact indexed/committed,
EOL-normalized and installed artifact representation without reopening accepted
behavior or adding variants. Reuse unaffected candidate-bound evidence; compare
actual payloads and run the applicable existing final-byte gates in disposable
state. A default host run's skipped reviewer cases remain skipped even when its
exit is zero; retain separately invoked preload-dependent witnesses accurately.
The common host set also excludes `test/k06-host.test.mjs` and the K07
host/recovery/storage files; use the existing `QE_TEST_FILES` selector explicitly
or the exact accepted bounded direct invocation. Name separately selected scopes
and required preload/child-environment support; wrapper0 does not replace inner
native exit/count/pipe readback. Source-only, exact tar/native-input equivalence
and actual installed feedback remain different observations. A retained material-change control removed
from the current owner file remains separate case-bound evidence, never silently
part of the current suite count. Reuse its exact accepted body/support with fresh
contained output allocation, not a reconstructed oracle or restored product test.
Qualify the actual final text reaching a contributed receiver, current declaration
approval and unresolved-capacity refusal at their owning boundaries. Native
context preparation/queue acknowledgment is not input inclusion. Actual installed
loading and exact artifact/input equivalence do not become an installed-feedback
observation; preserve the accepting owner's disclosed distinction.

Select `test/k08-role-neutrality.test.mjs` for current connected installed public
roles/admission/lifecycle/sink/prompt checks and
`test/k08-output-cap.test.mjs` for ordinary SDK cap/reasoning serialization. They
are explicit checkpoint families, not default common-host coverage. Count their
reporter parent separately from logical cases. Inspect actual packed/installed
bytes and inner native exit/pipe receipts; registration alone is not contribution
behavior. Static public-file prompt deployment does not qualify protected
package-directory reads, and role labels do not certify cross-process discovery.

For typed-assessor representation changes, use the existing compiled
`test/k09-typed-assessor.test.ts` family with its baseline helper, then select
`test/k09-typed-native.test.mjs` and `test/k09-typed-installed.test.mjs` as applicable.
The latter packs/extracts and links existing public peers; it is not dependency
installation or live Jev usefulness. Compare actual payloads, complete SDK-input
measurement and native receipts, not package versions. Reuse unchanged accepted
behavior. Frozen finance tests can write inheritance reports: never rerun them in
place; any necessary new discriminator needs fresh owned output and custody.

Ordinary tests run offline without billable credentials. Never silently replay a
stored answer on a failed live route. Paid experiments require explicit approval,
exact route, inputs, request/spend/time limits and actual termination conditions.
Do not activate donor plugins to supply a missing core capability.

Use isolated Pi settings and projects, an environment allowlist and fixture-specific
output directories. Do not inherit personal skills, providers, extensions or user data.
Set isolation before importing the SDK; do not inherit NODE_OPTIONS. Deliberately
non-repository fixtures must not discover an ancestor checkout: place temporary
state outside it or constrain Git discovery to the owned temporary-root ceiling.
Do not change production or an assertion to compensate for ambient discovery.
Bound waits and cleanup; no unowned background processes. Report discovered/executed,
passed/failed/skipped/TODO tests and limitations, not just a green process exit.
Reuse unchanged accepted fixtures and SDK facts in iterative repairs; run the named
corrected cases and concrete regression risks, then required checkpoint gates.
Preserve harness-only failures separately from product failures. Environment/path
incidents do not authorize reading or cleaning preexisting unrelated data.
Give each producer/helper a fresh explicit absolute native output; automatic
routing regressions run only in new owned mirrors with genuine earlier-stage
byte controls. Author-produced reviewer-named output remains author evidence.
Never rerun historical producers/sealers over sealed bundles or extend a seal.
Use actual protected-state and physical final-close witnesses, independently of
history suffixes. Preserve known loss, unsettled ownership and source-selection
negative controls; metadata/version expectation synchronization is not authority
to weaken a behavioral assertion.

Accepted checkpoints/tags require all named cases for one exact commit/artifact,
not a sum of earlier green runs. Exercise genuine timer/evaluator/provider/effect
boundaries and fitting/overflow resource controls; manifest identity and size must
match actual inputs. A syntax-shaped ID is not reference ownership. Store generated
evidence under ignored verification/;
small sanitized factual summaries may be deliberate documentation deliverables.
